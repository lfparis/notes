01 · The one idea

Two kinds of knowledge

A model knows things in two ways: what training fixed in its weights, and what you send in its context window on each call. In-context learning uses the second, the only part you control.

A large language model (LLM) is a program trained to predict the next piece of text. Everything it can draw on for a request comes from one of two places.

  • Its weights (also called parameters): billions of numbers set during training. They hold what the model absorbed from its training data, in compressed and blurry form. They are fixed when training ends, so they have a cut-off date and you cannot edit them.
  • Its context window (or just “the window”): all the text sent with this one request, such as instructions, the conversation so far, pasted documents, tool results and examples. The model can use this precisely and at once, but only for this call.

A useful picture: the weights are a library the model read once, long ago; the context window is the desk in front of it now. In-context learning is the model’s ability to pick up a task, a format or new facts from what is on the desk, without any change to the library. The 2020 GPT-3 paper that made the idea famous showed a model doing new tasks from instructions and a few examples in the prompt, with no further training at all.⁠1

Every call starts from scratch

The model itself remembers nothing between requests. Each call starts from the same frozen weights and sees only what is sent with it. A chat feels continuous because the harness (the program around the model, such as a chat app, a coding agent or your own code calling an API) sends the whole conversation again on every turn. Vendors’ documentation says so plainly: each request is “independent and stateless”, so “you always send the full conversational history”.⁠23 Even when a vendor stores the history for you, the earlier conversation is fed back in and billed again.⁠2

“Memory” features do not change this. They save notes outside the model and put the relevant ones back into the window on later calls.⁠4 That is still in-context knowledge, fetched automatically (see Memory and project files).

02 · How in-context learning works

Next-token prediction, with the whole window in view

The model predicts one token at a time, looking back over everything in the window as it goes. Examples work because the likeliest continuation of a pattern is more of the same pattern.

Tokens

Models read tokens: chunks of text that may be a word, part of a word or a punctuation mark. Window sizes and prices are counted in tokens; in English, “100 tokens are approximately 75 words”.⁠7

Next-token prediction

An LLM does one thing over and over: given the tokens so far, it estimates how likely each possible next token is, picks one, adds it to the end and repeats. In-context learning falls out of this loop: the likeliest continuation of “here are three worked examples, now a fourth input” is an output in the same pattern.

Attention: looking back over the window

The part of the model that uses the context is attention. For each new token, attention looks back over every earlier token, decides how much weight to give each one and blends in information from the ones that matter. A model does this many times over, in parallel units called heads, stacked in dozens of layers. Because each token is compared with every token before it, doubling the length roughly quadruples the attention work, and attention is spread more thinly as the window fills: what Anthropic calls an “attention budget” that “every new token introduced depletes”.⁠89

Zero-, one-, few- and many-shot

The GPT-3 paper named prompts by how many worked examples, or “shots”, they contain: zero-shot is instructions only, one-shot adds one example and few-shot adds as many as fit, typically 10 to 100 in that model’s small window; more examples usually helped.⁠1 Today’s long windows allow many-shot prompts with hundreds or thousands of examples.⁠10

Why does it work? Four partial answers

Nobody fully knows. The GPT-3 authors left open whether the model learns new tasks on the spot or simply recognises patterns it saw in training.⁠1 Four explanations each have support, mostly from small models built for study, and a 2026 study found that small transformers (the network design behind today’s language models) can develop two distinct mechanisms for it.⁠11 Read them as complementary views rather than rivals.

Real, but a partial story

Induction heads

Some attention heads learn a copying rule: having seen A followed by B, predict B when A appears again. They emerge at the same point in training as a jump in in-context learning; the evidence is causal in small models and only circumstantial in large ones.⁠12 In larger models, related heads that encode the task matter more.⁠13

Most useful intuition

Locating the task

Training text is full of documents with a hidden topic or task, so the model learns to work out which one it is reading. Your examples are evidence about which known task you want, which fits the finding that examples help even when some labels are wrong.⁠1415

Simplified set-ups only; contested

Learning inside one pass

In simple line-fitting problems, one attention layer can mimic one step of training on the examples, so the model “learns” without changing its weights.⁠16 Whether real models do this is unproven.⁠17

Growing support

Task vectors

The model condenses the examples into one compact summary of the task, a “task vector”, which steers how it handles the new input.⁠1819

03 · What examples really teach

Examples set the format more than the facts

A few examples mainly teach the format and the set of possible answers, not facts. Their order and layout can swing results, so state the rule as well, and test.

In classic few-shot classification, replacing the example labels with random ones “barely hurts performance”. What the examples mainly show is the set of possible answers, what typical inputs look like and the format of the whole sequence.⁠15

That does not make labels irrelevant. Larger models will follow examples even when the labels are deliberately flipped,⁠20 and predictions “almost always depend on in-context labels”.⁠21 Use correct labels: wrong ones can mislead.

Order, format and built-in biases

  • Order. The order of the examples “can make the difference between near state-of-the-art and random guess performance”, and a good order for one model does not carry over to another.⁠23
  • Bias. Models lean towards the label most common in the examples, the label nearest the end and labels common in their training data.⁠22
  • Formatting. Changing only the formatting of a few-shot prompt moved one 2023 open model’s accuracy by “up to 76 accuracy points”, and the sensitivity remained as models grew;⁠24 a 2024 study found one newer model more robust to template changes than its predecessor.⁠25

Many-shot

With hundreds or thousands of examples, many-shot prompting can override habits from training, and the best results often needed “hundreds of thousands of tokens”; order still mattered.⁠1026 Cost grows with every example, so caching matters (see Cost, latency and prompt caching).

Rules versus examples

A September 2026 preprint (a paper not yet peer-reviewed) found that “models generally learn more reliably from rules than from examples alone”, with no consistent gain from adding examples on top.⁠27 Vendor advice agrees: state the rule, use examples to illustrate it, and make sure the two agree.⁠28

Chain of thought, and reasoning models

Chain-of-thought prompting shows the model examples that include intermediate reasoning steps, so it writes out its own steps before answering. In 2022 it lifted large models sharply on maths word problems,⁠29 and simply adding “Let’s think step by step” took one model from 17.7% to 78.7% on an arithmetic test.⁠30 It works because each written step becomes new context the model can draw on. The gains turned out to be narrow: a review of over 100 papers found it helps mainly on maths and formal logic.⁠31

Reasoning models (also called thinking models) now produce their own hidden or summarised reasoning before they answer, often learned through reinforcement learning (training by trial and reward) rather than from human-written examples.⁠32

Vendors agree you no longer need to ask a reasoning model for step-by-step reasoning, but they differ on examples: OpenAI says try zero-shot first, Anthropic says examples work with thinking, Google’s general advice is to always include them, and the DeepSeek-R1 paper found few-shot prompting degraded its model.⁠28323334

In practice

State the goal and constraints, not a step-by-step script

Reasoning models plan for themselves; for them, chain-of-thought prompting “often results in only marginal, if any, gains” but “significantly increases the time and tokens needed”.⁠35

Control depth with the effort setting

Vendors offer a reasoning-effort control. OpenAI’s current guide says to compare settings on representative tasks “instead of assuming that the highest effort is always the best tradeoff”.⁠36

Leave room for thinking

Reasoning tokens take space in the window and are billed as output; OpenAI suggests reserving “at least 25,000 tokens for reasoning and outputs” at first.⁠37

Test order and wording before trusting a prompt

Shuffle the examples, try a second format and balance the labels. A prompt tuned on one model is not tuned for the next.⁠2324

04 · The window has limits

A bigger window is not a better-read window

Models accept far more text than they use well, and every token costs money and time on every call. Keep the input lean, and keep the start of the prompt unchanged so it can be cached.

Size is not the same as use

Advertised windows grew from 2,048 tokens in 2020⁠1 to a million tokens in commercial models from 2024, when Google previewed one;⁠38 other vendors followed in 2025.⁠3940 Most leading models now pass the popular “needle in a haystack” test, which hides one fact in long filler, so it says little. On harder tests, only half of 17 models claiming windows of 32,000 tokens or more held up at that length,⁠41 and most long-context models did far worse when the question and the hidden fact shared few words.⁠42

Lost in the middle

A 2023 study found a U-shaped curve: models did best when the key information sat at the start or end of a long input and worst when it was in the middle; in the worst case one model scored below the 56.1% it managed with no documents at all.⁠43 One cause is a built-in pull of attention towards the start and end “regardless of their relevance”.⁠44

Weaker now, but not gone

Newer studies point different ways. Scale and chain-of-thought prompting reduce the effect, and one October 2026 study found thinking models “nearly immune” to it,⁠46 yet a May 2026 study still saw drops of 16 to 56 points in the middle with some kinds of filler.⁠47 Treat position as a risk to test for, not a fixed law.

Context rot

Even with difficulty held constant, more text hurts. Chroma’s 2025 tests of 18 models found that “model performance consistently degrades with increasing input length”; on one memory test, models did far better with a focused prompt of about 300 tokens than with the full 113,000.⁠48 Passages that look relevant but are not, called distractors, hurt, some more than others.⁠48 Performance falls even when the model can retrieve every relevant fact perfectly.⁠49 This gradual decline is often called context rot.

Cost, latency and prompt caching

Every input token is processed and billed on every call, so a long system prompt is paid for again on every turn, and the wait before the reply starts grows with the prompt’s length.⁠50 Some vendors also charge more per token for very long prompts.⁠51

As the model reads a prompt, each layer computes intermediate values for every token, called keys and values; the store of them is the KV cache. Prompt caching keeps this store for the beginning of a prompt (its prefix) after a request ends, so the next request that starts with exactly the same tokens can skip that work. What is kept is the model’s intermediate working, not your text and not an answer, so the reply is still written fresh.⁠52

Matching is exact and runs from the start. Change one early token, such as a timestamp or a reordered tool list, and everything after it misses the cache. Hence the rule all three big vendors give: static content first, variable content last.⁠525354

  • 79%

In practice

Tools, instructions, reference documents and examples first; timestamps, user details and the new question last

Caching only hits on an exact prefix.⁠53

Append to the conversation instead of rewriting it

“Summarization, compaction, or context truncation can change the prefix and reset cache reuse.”⁠52

Check that caching is actually happening

The API’s usage figures show how many input tokens came from the cache. Short prompts (under 512 to 4,096 tokens, by vendor and model) are not cached, and entries expire after minutes to hours.⁠525354

Test at your real length

Needle-in-a-haystack results “do not reliably predict downstream performance”.⁠55

05 · Context engineering

What fills the window, and who decides

In an agent, the user’s question is a small part of what the model reads. Context engineering is choosing everything else: what goes in, in what order, and what stays out.

Prompt engineering is writing and organising the instructions. Context engineering is the wider job of deciding what goes into the window at each step (instructions, examples, retrieved documents, tool definitions, memory, history, tool results) and what is left out, summarised or moved elsewhere. The term caught on in June 2025.⁠56 It contains prompt writing rather than replacing it.⁠957

What actually fills the window

Roughly from the most stable to the most changeable:

Every call · developer

System prompt

Role, goal, rules and output format.

Every call · developer and connected servers

Tool definitions

Name, description and arguments for every tool. In one of Anthropic’s examples, 58 tools took about 55,000 tokens “before the conversation even starts”.⁠58

Every call · harness

Skill and subagent descriptions

One line each; the full instructions load only when used.

Session start · harness

Project instructions and memory

Files such as AGENTS.md, and an index of saved notes.⁠59

Every call · developer

Examples

A few worked inputs and outputs that show the format and the judgement you want.

Per question · harness or model

Retrieved documents

Passages found for this question by search, or fetched by the agent with its tools.

Grows every turn

Conversation and tool results

In agents this grows fastest: one agent builder reports about 100 input tokens for every output token.⁠60

Last

The latest message

What the user asked, plus room for the reply and any reasoning.

Smallest does not mean short: every token should earn its place, because each one competes for attention (see The window has limits).

Four ways to manage the window

Most context-engineering techniques fall into four buckets, “write, select, compress, and isolate”.⁠61

Save it outside the window

Write

Notes, plans and memory files that survive a reset. Example: a to-do file the agent keeps updating.

Bring in only what this step needs

Select

Retrieval, skills, tool search, reading one file instead of the whole folder.

Shrink what is already there

Compress

Clearing old tool results, summarising history.

Give a side task its own window

Isolate

A subagent explores and returns only a summary.

Behind “select” is an idea you will meet again in tool search, skills, folder-specific instruction files and subagents: keep lightweight references in the window, such as file paths, saved queries and links, and load the content only when it is needed.⁠9

In practice

Treat the window as a budget

Include what changes the answer; leave out what does not. “More context isn’t automatically better.”⁠62

Keep precise timestamps out of the start of the prompt

A timestamp “precise to the second” at the top of the system prompt is “a common mistake”, because it breaks the cache on every call.⁠60 If the model needs the date, put it near the end.

06 · System prompts and instructions

Write for a smart colleague who has just arrived

Start with the smallest prompt that works on a strong model, and add instructions only for failures you have seen. Say what to do and why, and test every change on real cases.

The system prompt (OpenAI calls it the developer message; Google, the system instruction) is the standing set of instructions the harness sends before the conversation. Since 2025 the main vendors have agreed on one point above all: start small. Test “a minimal prompt with the best model available”, then add instructions and examples “based on failure modes found during initial testing”.⁠9 OpenAI warns that “overly specific guidance can now hinder results where it previously helped”, and Google that newer models may “over-analyze” elaborate techniques written for older ones.⁠6364

A good test, from Anthropic: show the prompt to a colleague who knows little about the task. If they would be confused, so will the model.⁠33

The right level of detail

Aim between hard-coded, brittle logic and guidance so vague that it gives the model nothing concrete to go on.⁠9 Describe the outcome, how success is judged and the shape of the output; OpenAI’s current guide says its newer models infer intent well enough that you “often do not need to prescribe every step”, while still giving context, hard limits and success criteria.⁠36

Practices that hold across vendors

In practice

Lead with the goal, then context, constraints, success criteria and output format

OpenAI’s current guide lists the same parts: “state the goal, relevant context, constraints, required evidence, success criteria, and output format”.⁠36 A role sets tone and scope, not accuracy: assigning expert personas “does not reliably improve accuracy”.⁠65

Give the reason behind each rule

“NEVER use ellipses” works less well than explaining that a text-to-speech engine will read the reply aloud and cannot pronounce them; the model “can generalize from the explanation”.⁠33

Say what to do, not only what not to do

Instead of “Do not use markdown”, write “Your response should be composed of smoothly flowing prose paragraphs.”⁠33

Drop the shouting

Current models over-react to ALL CAPS and “CRITICAL”: write “Use this tool when…”, not “CRITICAL: You MUST use this tool when…”.⁠33

Remove contradictions, or say which instruction wins

OpenAI found that one 2025 model tends to follow whichever of two conflicting instructions comes later in the prompt;⁠66 reasoning models spend tokens “searching for a way to reconcile the contradictions”.⁠67

Set machine-readable formats through the API, not the prompt

Structured outputs restrict the reply to a JSON schema (a description of the fields and their types), so it always parses; the content still needs checking in code.⁠6869 Strict formats can cost accuracy: two 2026 studies, mostly on open-weight models (models whose weights are published), traced most of the loss to the format instructions themselves and to layouts that put the answer before the reasoning.⁠7071 If you need a strict format, put a reasoning field before the answer field.

Leave temperature alone on reasoning models

Temperature controls randomness. As of November 2026 the three big vendors either reject non-default values on their newest models or advise against changing them.⁠366472

Long documents: where do they go?

Vendors disagree: Anthropic and Google put the documents first and the question last (see Lost in the middle);⁠3334 OpenAI’s 2025 guide puts instructions both before and after them.⁠66

A layout that suits all three

A short statement of the task, then the documents (each wrapped in tags with its source), then the full instructions and the question. For long inputs, also ask the model to quote the relevant passages before it answers.⁠73

This layout is for the message that carries the documents. Your standing system prompt still goes first and stays unchanged, so the start of the prompt can still be cached.

A weak prompt made stronger

An invented example: a bike shop’s website chat that answers from policy pages the app retrieves and passes in. The app sets the reply format (the fields reply_text, needs_human and handover_reason) through the API’s structured-output feature, and sends the policy documents first and the customer’s message last.

Test it like code

An evaluation (or eval) is a test: an input, a run and some grading logic.

Rule of thumb

Start with 20 to 50 real cases

“20-50 simple tasks drawn from real failures is a great start.”⁠74

Test both sides

Include cases where a behaviour should happen and where it should not.⁠74

Grade with code where you can; check model judges against people

A model used as a judge favours some answer positions, longer answers and its own answers.⁠75 Compare its grades with a person’s, and let it answer “Unknown”.⁠74

Read the transcripts, and re-test on every model change

Failures are often in the grading: fixing grader bugs once moved a score from 42% to 95%.⁠74 Keep prompts in version control and pin model versions.⁠76

07 · Memory and project files

Standing instructions, read at the start of every session

Project instruction files such as AGENTS.md give an agent the facts it cannot find out for itself. The model can still ignore them, so keep them short and enforce hard rules elsewhere (see Hooks).

Project instruction files are Markdown files the harness loads automatically at the start of a session, so you do not have to repeat yourself. They are context, not configuration: the model reads them and usually follows them, but nothing forces it to. Claude Code’s documentation notes that its file “is delivered as a user message after the system prompt” and that “there’s no guarantee of strict compliance”.⁠77

AGENTS.md is the cross-tool convention: “a README for agents”, in plain Markdown with no required fields.⁠78 OpenAI released it in August 2025; by December 2025, when it joined the Agentic AI Foundation, “more than 60,000 open source projects and agent frameworks” had adopted it.⁠79 Most tools read it alongside their own equivalents, such as CLAUDE.md, GEMINI.md, Cursor rules and Copilot instruction files.

Files usually stack from broad to specific (organisation, user, repository, subfolder): “The closest AGENTS.md to the edited file wins; explicit user chat prompts override everything.”⁠80 Some tools load a subfolder’s file only when the agent first works in that folder, which keeps the rest of a large repository’s instructions out of the window until needed.⁠81

Example: a short AGENTS.md (invented)

# Project notes for agents​## Commands- Install: `make setup`- Test one package: `make test PKG=billing`- Lint before committing: `make lint`​## Boundaries- `src/generated/` is generated by `make codegen`; never edit it by hand.- `billing` may import `core`, never the other way round.​## Definition of done- Tests and lint pass; any new endpoint has a test.- Ask a person before changing database migrations.

Studies disagree

A February 2026 study found that context files did not generally improve success rates and raised costs by over 20% on average, and that repository overviews “are not helpful”.⁠82 A January 2026 study found AGENTS.md files cut median run time by about 29% while the agents completed tasks about as well.⁠83 Both point the same way on content: include only what the agent cannot find out for itself.

In practice

Keep it short

Claude Code targets “under 200 lines per CLAUDE.md file”, because “Longer files consume more context and reduce adherence”;⁠77 Codex stops reading at 32 KiB by default.⁠84

Include only what changes behaviour

Exact commands, non-obvious boundaries, the definition of done, actions that need a person.⁠85 Leave out directory listings and anything a linter enforces.

Enforce what must always hold elsewhere

Instruction files should not replace access controls, automated checks or other enforcement.⁠85 Use a hook, a permission setting or a test.

Review instruction files like code

Hidden Unicode characters in rules files have been shown to steer coding agents into inserting malicious code.⁠86

Memory the agent writes itself

Some harnesses let the agent save its own notes, such as preferences, project facts and lessons, as files it reads back later. Usually only a short index loads at the start, with detail fetched on demand;⁠77 at API level, Anthropic’s memory tool lets the model create, read, update and delete files your application stores.⁠4 OpenAI’s advice: “Treat memories as a helpful recall layer, not as the only source for rules that must always apply.”⁠87 All of this is text put back into the window; the weights do not change.

A saved note can be wrong, out of date or planted on purpose, and it is read back into later sessions; OWASP’s agentic Top 10 lists memory and context poisoning, in which an attacker plants misleading data that “propagates across sessions”.⁠88 Review what the agent has saved, and prefer tools that let people see, edit and expire memories: GitHub’s agent checks a memory’s citations before relying on it, and memories expire after 90 days by default unless reinforced.⁠89

08 · Retrieval (RAG)

Look it up, then answer

Retrieval finds relevant passages when a question arrives and puts them in the window, giving the model fresh, private and citable knowledge. Most of the quality comes from the search, not the model.

Retrieval-augmented generation (RAG) looks up relevant text when a question arrives and puts it into the prompt, so the model answers from that text. The knowledge is fresh (update the documents, not the model), private (your own files) and citable (you know which passage an answer came from).⁠90

The search vocabulary

chunk

A passage cut from a document, small enough to search and to fit several into a prompt. Start at a few hundred tokens, split on natural boundaries; studies disagree on the best size.⁠92939495

embedding

A list of numbers representing a text’s meaning, so that texts with similar meanings sit close together.⁠96

vector search

Finding the chunks whose embeddings sit nearest the question’s. Good at paraphrase; can miss exact identifiers and rare terms.

keyword search (BM25)

A long-established formula that scores text by the query’s words, rare words counting more. Excellent at exact matches such as error codes.

hybrid search

Running both and merging the two ranked lists.⁠97

reranker

A slower, more accurate model that reads the question and each candidate together and re-scores the top results.

Search quality comes first

In vendor tests on their own data, combining keyword and vector search beat either alone, and adding a reranker helped most; on queries for exact terms, vector search alone did badly.⁠92 Anthropic tried adding a short, model-written note to each chunk, saying where it sits in its document, before building both indexes. That cut failed searches (the right passage missing from the top 20) by 49%, from 5.7% to 2.9%, and by 67%, to 1.9%, with a reranker added.⁠91

Practices

In practice

First ask whether you need retrieval at all

If your material is “smaller than 200,000 tokens (about 500 pages of material)”, one vendor suggests putting it all in the prompt with caching.⁠91

Build a small test set before tuning anything

Real questions, their expected answers and the passages that contain them; every choice below depends on your data.⁠98

Give each chunk its context; use hybrid search and a reranker

Prefix each chunk with a short note on where it sits in its document, or at least its title and section. Retrieve broadly, rerank and keep the best few: Anthropic retrieved 150 and kept 20.⁠91

Do not over-fill the window, and label what you include

Quality rises, then falls, as passages are added, because near-misses mislead.⁠99100 Tag each chunk with its source and date, and put the documents before the question.⁠33

Ask for citations, allow “I don’t know”, and say how to handle conflicts

Strong models “often output incorrect answers instead of abstaining”;⁠101 permission to admit uncertainty helps.⁠73 Models also accepted wrong retrieved text over their own correct knowledge “over 60% of the time” in one study,⁠102 so do not rely on the model to catch bad sources: date each passage, tell the model to prefer the newest and to flag disagreements, and keep the index clean.

Enforce permissions at retrieval time, not in the prompt

Filter results by what the asking user may see before they reach the model.⁠103 A model told not to reveal something is not access control.

Agentic retrieval

Instead of one search up front, you can give the model search tools and let it look things up, read the results and search again: “just in time” context.⁠9 Anthropic’s coding agent loads project instruction files up front, then finds files with simple commands such as grep (which finds lines matching a pattern); this avoids a stale index but is slower than pre-computed retrieval.⁠9 Cap what such tools return: one open-source coding agent returns at most 50 results; if more match, it shows none and asks for a narrower query.⁠104

Still argued over

Do agents still need a vector index? In Cursor’s own tests, adding vector search to grep gave 12.5% higher answer accuracy on average, and in a live trial the gain in code that users kept was largest on big codebases.⁠105 A May 2026 study found grep generally beat vector search inside agents, though on a conversation-memory test rather than code.⁠106 Simple search tools are strong; a good index can still help at scale.

09 · Tools and function calling

The model writes the request; your code runs it

The model can only write a request to call a tool; your code decides whether to run it. Tool descriptions are sent on every call, so offer a few clear tools rather than many vague ones.

The model cannot run anything; it can only write text. Function calling (also called tool calling or tool use) is a convention that lets it write a structured request to run a function, which your code then carries out. Anthropic’s documentation: the model “returns a structured call that your application runs”.⁠112 (Vendor-hosted “server tools”, such as web search, are run by the vendor instead.) An agent is essentially this loop running for many steps.

What a tool definition contains

A tool definition has three parts: a short, unique name; a plain-language description of what the tool does, when to use it and when not to; and an input schema, a JSON Schema (a standard description of a JSON object’s shape) listing the arguments, their types and which are required. Definitions sit in the context window, so “callable function definitions count against the model’s context limit and are billed as input tokens”.⁠113

Two settings matter. Tool choice lets the model decide, or makes it call a tool, a particular tool or none.⁠113 Not every model supports forcing a call: as of November 2026 Anthropic’s newest models do not, and it recommends letting the model decide.⁠114 Strict mode guarantees that the arguments match the schema; OpenAI recommends always turning it on.⁠113

Designing tools models use well

Example: a weak and a better tool description (invented)

Weakname: searchdescription: Searches.​Bettername: tickets_searchdescription: Search support tickets by keywords, customer email or status. In practice

Write descriptions as if for a new colleague

The description is “by far the most important factor in tool performance”; aim for “at least 3–4 sentences” per tool.⁠113114

Build a few tools for whole tasks, not one per API endpoint

One schedule_event tool beats list_users, list_events and create_event.⁠115

Make names and parameters unambiguous

Prefix names by service (tickets_search), use user_id rather than user, use fixed lists of values, and do not ask for values your code already knows.⁠113115

Return little, say how to get more, and make errors useful

Return high-signal fields with sensible limits; Claude Code caps tool responses at 25,000 tokens by default.⁠115 An error should say how to fix the call, so the model can correct itself.⁠116

Keep the starting list short and stable

OpenAI suggests “fewer than 20 functions available at the start of a turn”;⁠113 Anthropic says selection “degrades once you exceed 30–50 available tools”.⁠117 Usage examples in definitions help with tricky parameters.⁠58

Tool search handles large tool collections: most definitions are held back, and the model first searches for the few it needs. In Anthropic’s example this cut tokens by 85% and improved tool selection.⁠58 It is just-in-time loading, applied to tool definitions.

10 · MCP

One plug for many tools: the Model Context Protocol

MCP is an open standard that lets any compatible app use any compatible tool server. It solves the wiring, not the judgement: connected tools still take room in the window, and every server is code you trust.

Without a standard, every AI application needs its own connector for every tool or data source: with M apps and N tools, up to M × N integrations. With a shared protocol, each tool is wrapped once as an MCP server and each app implements MCP once as a client, so the work becomes roughly M + N.⁠118

Anthropic open-sourced MCP in November 2024⁠118 and in December 2025 gave it to the Linux Foundation’s new Agentic AI Foundation, by which time there were “more than 10,000 active public MCP servers”.⁠119

What a server can offer

The specification defines three kinds of server feature.⁠120121

tools

Functions the model can call. The model decides when.

resources

Read-only data or context, such as file contents or records, that the host pulls into the window.

prompts

Reusable prompt templates that users invoke explicitly, often shown as slash commands.

A server can run on your own machine, started by the host as a separate program, or remotely, reached over the web.⁠122 Remote servers can use OAuth, the familiar step in which you allow an app limited access to your account, though the specification makes authorisation optional; local servers take credentials from their environment instead.⁠123

Changed recently

As of November 2026 the current specification is version 2026-07-28,⁠124 a major revision. It dropped the opening handshake and the sessions between client and server, making remote servers easier to run at scale,⁠125 and deprecated three features (sampling, roots and logging), which keep working for at least twelve months.⁠126 Older clients are still in use, so the new version keeps a backward-compatible mode for them,⁠127 and the maintainers’ roadmap promises more change.⁠128

The context cost

Connecting a server puts all its tool definitions into the window on every call: with a hundred tools, “the model pays for that entire surface before the user has asked a single question, and tool selection tends to get worse as the list grows”.⁠128 Tool results pass through the window too: copying a two-hour meeting transcript from one tool to another “could mean processing an additional 50,000 tokens”.⁠129

Simplest

Connect fewer servers

Connect only what the task needs. Every server’s tools are in the window on every call.

Tool search

Load tools on demand

Only a search tool is loaded at first; the model finds the few tools it needs (see Tools).

Code execution

Call tools from code

The tools are presented as code files that the model reads only when it needs them, and it writes a short program that calls them in a sandbox (an isolated place with limited file and network access). Loading only the definitions it needed cut one example from 150,000 tokens to 2,000, by Anthropic’s count.⁠129 The program can also filter data before anything reaches the window. Cloudflare reached a similar view.⁠130 You need a secure sandbox for model-written code.

In practice

Prefer servers from verified publishers, pin versions and read the tool descriptions

The official MCP Registry verifies who publishes a server but leaves security scanning to package registries and marketplaces.⁠131

Run local servers in a sandbox, and see the exact command before installing

A local server is a program running with your privileges; the MCP project’s security guidance asks clients to “Show the exact command that will be executed, without truncation”.⁠132

Ask for the narrowest permissions

The same guidance calls for “a progressive, least-privilege scope model” and names wildcard scopes as a common mistake.⁠132

11 · Skills and slash commands

Know-how that loads only when it is needed

A skill is a folder of instructions for one kind of task; only its name and a one-line description sit in the window until it is needed. A slash command is a saved prompt you trigger yourself.

A skill packages instructions for one kind of task. The only required file is SKILL.md: a short block of metadata at the top (front matter, written as key: value lines between --- markers), followed by Markdown instructions. Optional folders hold scripts the agent can run, reference documents it reads on demand, and assets such as templates.⁠133

The design idea is progressive disclosure: load detail only when it is needed.

Example: SKILL.md (invented)

---name: release-notesdescription: Drafts release notes from merged pull requests and the changelog. Use when the user asks for release notes, a changelog summary or "what shipped" in a version. Not for commit messages.---​# Drafting release notes​1. Run `scripts/collect_prs.py <from-tag> <to-tag>`; it prints one line per merged pull request. Run it; do not read its source.2. The description (up to 1,024 characters) “Describes what the skill does and when to use it”.⁠133 The model usually decides when to use a skill by matching the task against it; most tools also let you call a skill by name, and let its author turn either route off.⁠135

In practice

Make the description say what the skill does and when to use it

It is the only part the model sees before choosing; “the description carries the entire burden of triggering”.⁠136 Use the words a user would type.

Keep SKILL.md short, most important instructions first

The specification suggests under 500 lines and 5,000 tokens, with detail in reference files “one level deep”.⁠133 After compaction, Claude Code may keep only the start of a skill.⁠135

Add only what the model would get wrong without it

“Would the agent get this wrong without this instruction? If the answer is no, cut it.”⁠137 Concrete pitfalls beat general advice.

Ground skills in real expertise, then test them

In SkillsBench, curated skills raised average pass rates “from 33.9% to 50.5%”, and focused skills beat exhaustive ones;⁠138 an earlier version of the study found that skills a model wrote for itself gave no benefit on average.⁠139 Test with tasks that should and should not trigger the skill.⁠136

Treat third-party skills as code

A January 2026 study of 31,132 public skills found “26.1% of skills contain at least one vulnerability”.⁠140 Read every file before installing.

Slash commands and saved prompts

A slash command is a saved prompt you trigger by typing / and its name; the harness expands it and sends it as if you had typed it, so it costs nothing until used. Commands are now being folded into skills: Codex says “Custom prompts are deprecated. Use skills for reusable instructions”,⁠141 and Claude Code and Cursor have made the same move.⁠135142 What remains different is who starts it: keep workflows with side effects, such as a deploy, for the user to trigger.⁠135

Changed recently

Anthropic launched Agent Skills in October 2025 and published the format as an open standard in December 2025.⁠143 In October 2026 it gave the standard to the Agentic AI Foundation, saying more than 70 agent platforms had integrated it. As of November 2026, versioned releases and security guidance are still only proposed,⁠144 and fields a vendor adds beyond the specification do not work elsewhere.⁠135

12 · Hooks

Instructions are requests; hooks are guarantees

A hook is your own code that the harness runs at fixed points, such as before every tool call. It runs every time, regardless of what the model decides, so use it for rules that must always hold.

A hook is a script that the harness runs automatically at fixed points in a session. It receives a description of the event, such as the command about to run, and can allow it, block it, change it or add text to the context. Because the harness runs it, not the model, a hook is deterministic: it runs every time its event happens, whatever the model decides (except prompt-based hooks, in which a model judges a condition; those behave like instructions).⁠145146 As Claude Code’s documentation puts it, an instruction like “never edit .env” “is a request, not a guarantee. A PreToolUse hook that blocks the edit is enforcement.”⁠147 A hook costs no context unless it prints something back.⁠147

In practice

Decide and test what happens when the hook fails

Several tools fail open: if a hook crashes or times out, the action can go ahead anyway, and in some tools a malformed reply does too.⁠148150

Keep hooks fast, narrow and quiet

A slow hook slows every action, so use matchers (patterns that say which tools or files a hook applies to) to run it only where needed;⁠146149 anything it prints lands in the context and costs tokens.⁠147

Review project hooks before trusting a repository

Hooks run with your permissions. In February 2026, researchers showed that a repository’s settings, hooks included, could run commands and leak API keys “simply by cloning and opening an untrusted project” (since fixed).⁠151 Several tools now ask before running a repository’s hooks, and ask again when they change.⁠148149

Do not assume a hook works in another tool

Event names, payloads and exit codes differ, although exit code 2 means “block” in several tools.⁠146148149150152

13 · Plugins

Package it once, share it with the team

A plugin bundles skills, commands, subagents, hooks and MCP settings so a team can install a whole set-up at once. Every enabled plugin takes room in the window, and any hooks, servers or scripts it contains run with your permissions.

A plugin is the packaging layer: one install that adds a set of slash commands, skills, subagents, MCP servers and hooks. Claude Code introduced them in October 2025,⁠153 and Codex and Gemini CLI (which calls them extensions) offer similar bundles.⁠154155 Google is moving most Gemini CLI users to its Antigravity CLI, where extensions become plugins.⁠156 A marketplace is a catalogue of plugins and where to fetch them; in Claude Code it is just a git repository with a listing file.⁠157 Start with individual files; make a plugin when a second repository or a team needs the same set-up.⁠147

In practice

Install only from marketplaces you trust, and read what a plugin contains

A plugin “can run code with your user privileges”: check its hooks, MCP servers and scripts first.⁠157 Organisations can allow-list marketplaces centrally.⁠157

Disable plugins you are not using

The name and description of every skill, subagent and command a plugin lets the model start on its own stay in the window on every turn, and its servers and hooks keep running.⁠157

Still settling

A cross-vendor format, Agent Plugins 1.0, was published in July 2026.⁠158159 As of November 2026 only its small core is portable: a manifest (the file that describes the plugin), skills and MCP server settings. “Slash commands, custom agents and hooks remain client-specific.”⁠159 For portability, put shared know-how in skills and MCP.

14 · Long-running work

When the task outlasts the window

Long tasks fill the window with history and tool output. When it fills, clear old tool results first, then summarise; from the start, keep notes in files and hand noisy side tasks to subagents.

Compaction, clearing and notes

Compaction summarises the conversation when the window fills, and work continues in a fresh window from the summary; it is lossy by design.⁠9 Tool-result clearing (also called context editing) deletes old tool outputs that have already been used, leaving a placeholder,⁠160 and is “One of the safest lightest touch forms of compaction”.⁠9 Structured note-taking has the agent write progress, decisions and to-do lists to files and read them back later.

  3. 03

  4. 04

Each later step keeps less of the original detail or costs more tokens overall. Notes and subagents work best when set up from the start, not only once the window is full.

In practice

Say what a summary must keep

Decisions, IDs, unresolved problems and the next step. A good template is the one Anthropic documents for its SDK compaction: a task overview, the current state, important discoveries, next steps and context to preserve.⁠160 (That SDK feature has since been removed from Anthropic’s Python SDK.)⁠72 A bad fact in a summary “can poison future behavior”.⁠161

Keep exact state in structured files

Compaction is a poor fit for tasks that “need to maintain exact state across many variables”.⁠160 In Anthropic’s experience, the model was less likely to overwrite a JSON file by mistake than a Markdown one.⁠162 A hook that runs before compaction can save state reliably.⁠146

Tell the agent that compaction exists

Otherwise it may wind its work down early as the window fills.⁠33

Consider starting fresh instead of summarising

Anthropic says its latest models are “extremely effective at discovering state from the local filesystem”.⁠33 After a wrong turn, restart with the full request in one message: models in multi-turn conversations “get lost and do not recover”.⁠163

Subagents

A subagent is a second agent that the main agent (or you) starts for a side task, with its own context window, its own instructions and often fewer tools. It may use “tens of thousands of tokens or more” exploring, but “returns only a condensed, distilled summary of its work (often 1,000-2,000 tokens)”.⁠9

Subagents usually start with a clean slate: they “don’t have access to prior conversation history”.⁠164 Their report goes to the parent, not to you.

Setting up a subagent

Describe when to use it

The main agent picks a subagent by its description, as it picks a skill, and those descriptions sit in the main window; Claude Code warns when they pass 15,000 tokens.⁠169

Brief it fully

Give it the goal, the constraints, where things are and what to return.⁠164165

Read-only helpers that gather and check information carry the least risk; keep decisions that depend on each other with the main agent.⁠168169

15 · Safety

Anything the model reads can give it orders

A model cannot reliably tell your instructions from instructions hidden in what it reads, and no prompt fixes that. Limit what the agent can do, put a person in front of risky actions, and never combine private data, untrusted content and a way to send data out.

Prompt injection is text the model reads that contains instructions the model then follows, whoever wrote them; the name, from 2022, echoes SQL injection.⁠170 In direct injection the user types the instruction; in indirect injection it hides in content the model processes, such as a web page, an email, a document or a tool description, and the user may never see it.⁠171172 It differs from jailbreaking (getting a model to break its maker’s rules): the attacker can be anyone who can put text in front of your agent.

The root problem is that everything arrives as one stream of tokens: “LLMs are unable to reliably distinguish the importance of instructions based on where they came from.”⁠173

The lethal trifecta

Simon Willison’s rule of thumb is that an agent becomes easy to turn into a data thief when it has all three of these: access to private data, exposure to untrusted content, and a way to send data out. “If your agent combines these three features, an attacker can easily trick it into accessing your private data and sending it to that attacker.”⁠173 The defence is to remove at least one of the three for each task. Because people mix tools from many sources, “the risk profile is a property of the session, not of any single server”.⁠174

Risks specific to tools and MCP

How MCP works is covered in MCP.

Hidden in a description

Tool poisoning

A malicious server hides instructions in a tool description, which the model reads in full and the user usually never sees.⁠175

Changes after approval

Rug pull

A server changes a tool’s description after you have approved it.⁠175 In September 2025 a fake package on a public registry “built trust over 15 versions, then added a backdoor” that copied users’ emails to an outside server.⁠176

Through an honest server

Toxic flow

An attacker’s public issue tricked an agent using a legitimate GitHub server into “leaking data from private repositories”.⁠177 All three parts of the trifecta sat in one server.

Why a better prompt is not the answer

A system prompt saying “ignore instructions in documents” is more text in the same stream. In 2025, researchers broke 12 recently published defences, most of them more than 90% of the time, although most had first reported that almost no attacks succeeded.⁠178 Vendors say the same of their own products: even the best browser agents are not immune, and prompt injection “is unlikely to ever be fully ‘solved’”.⁠179180

Defences that work

Break the trifecta for each task

For example, an agent that reads incoming email gets no tool that can send data out.⁠181

Give the fewest powers that do the job

OWASP traces excessive agency to “excessive functionality; excessive permissions; excessive autonomy”, and advises enforcing permissions outside the model.⁠182

Put a person in front of actions with real consequences

Sending, deleting, paying, publishing. The harness, not the prompt, should hold the action until a person approves it, showing everything the tool will receive.⁠116

Sandbox code and local servers; restrict where data can go

Run model-written code and local servers with limited file and network access, and allow-list destinations.⁠129132

Design so untrusted input cannot trigger actions

Once an agent has read untrusted input, constrain it so that the input cannot trigger actions with real consequences.⁠183 One such design solved 77% of benchmark tasks with provable security, against 84% undefended.⁠184

Keep secrets out of the window

Assume anything the model reads, the system prompt included, can be repeated to a user or an attacker. OWASP says the system prompt “should not be considered a secret” and that credentials “should not be contained within the system prompt language”; keep keys in the harness.⁠185

Mark untrusted content, and watch what changes

Wrap tool results and retrieved text in tags that say where they came from, and tell the model such content is data, not instructions; this lowers the risk without removing it.⁠171 Pin server versions, watch for changed descriptions,⁠175 and treat hints such as “read-only” as claims: “An untrusted server can lie”.⁠174

17 · Myths and facts

Five things people get wrong

Most mistakes with context come from treating the model like a database, a rule engine or a person who remembers.

Myth

The model learns from my chats permanently.

Fact

Its weights do not change while you use it; each call starts fresh and sees only what is sent. Memory features save notes outside the model and put the relevant ones back into the window.⁠24

Myth

A bigger window means the model reads everything equally well.

Fact

Models often use far less than they accept: accuracy falls as input grows, even on easy tasks, and the middle of a long input can be missed.⁠414348 Newer models show smaller position effects, but they have not gone.⁠47

Myth

RAG stops hallucinations.

Fact

It reduces them. Commercial legal research tools still got answers wrong “between 17% and 33% of the time”,⁠186 and models often trust wrong retrieved text over what they knew.⁠102

Myth

The model runs the tools, and MCP is part of the model.

Fact

The model only writes a request; the harness runs it (or, for vendor-hosted tools such as web search, the vendor does).⁠112113 MCP connects harnesses to tool servers; the model just sees ordinary tool definitions.⁠120

Myth

A good system prompt can stop prompt injection.

Fact

The prompt is more text in the same stream. Adaptive attacks broke 12 published defences, most of them more than 90% of the time.⁠178 Limit what the agent can do instead.

18 · Check yourself

Eight questions, answers hidden

A quick test of the main ideas.

  1. Q1You told a chat assistant your preferences yesterday and it remembers them today. Did its weights change?

    Answer

    No. Each call is stateless; a memory feature saved a note and put it back into today’s context window.

    See Two kinds of knowledge

  2. Q2Your key instruction sits in the middle of a 60-page prompt and is sometimes ignored. What do you try first?

    Answer

    Put the documents first and the instruction and question at the end (or state the task briefly before the documents and in full after). Then shorten the input, and test.

    See Write for a smart colleague who has just arrived

  3. Q3You are writing for a reasoning model. Should you include “think step by step” and a numbered plan?

    Answer

    Usually not. State the goal, success criteria and constraints, use the effort setting to control depth, and test zero-shot against a few examples (vendors differ).

    See Examples set the format more than the facts

  4. Q4Your knowledge base is about 150 pages and rarely changes. Do you need a RAG pipeline?

    Answer

    Probably not: put it in the prompt and use caching. Retrieval earns its keep for large, changing or permission-controlled collections.

    See Look it up, then answer

  5. Q5An agent keeps picking the wrong one of 80 connected tools. Name two fixes.

    Answer

    Any two of: connect fewer servers; load tools on demand with tool search; rewrite descriptions to say when to use each tool and when not to; remove overlapping tools.

    See The model writes the request; your code runs it

  6. Q6You need the agent never to edit files in secrets/. Where does that rule go?

    Answer

    In a hook or permission setting that blocks the edit, not in AGENTS.md. Then test what happens if the hook fails.

    See Instructions are requests; hooks are guarantees

  7. Q7When does a subagent help, and when does it hurt?

    Answer

    It helps when a side task would flood the main window and only a summary is needed back. It hurts when several agents make interdependent decisions, and it usually costs more tokens overall.

    See When the task outlasts the window

  8. Q8An agent reads incoming customer emails, can search your company wiki and can send email. What is wrong, and what do you change?

    Answer

    It has all three parts of the lethal trifecta. Remove one for this task, for example its ability to send email; if it must send, have a person approve every outgoing message.

    See Anything the model reads can give it orders

The part of a model that, for each new token, weighs every earlier token in the window. →
Chain of thought
Prompting a model to write out its reasoning steps before the answer. →
Compaction
Replacing older parts of a conversation with a summary so work can continue. Lossy by design. →
Context engineering
Choosing everything that goes into the window at each step, and what stays out. →
Context rot
The gradual fall in accuracy as the input grows, even on simple tasks. →
Context window
Everything the model can read on one call, measured in tokens. Often just “the window”. →
Deterministic
Behaving the same way every time. A hook runs every time its event happens; whether a model follows an instruction is not guaranteed. →
Embedding
A list of numbers representing a text’s meaning, so that similar texts sit close together. →
Eval
A test of a prompt or agent: an input, a run and some grading logic. →
Fail open
When a check that breaks or times out lets the action go ahead anyway. →
Few-shot prompting
Putting a handful of worked examples in the prompt; with hundreds or thousands, it is called many-shot. →
Fine-tuning
Further training on a smaller, task-specific dataset, which changes the model’s weights. →
Function calling
Letting a model write a structured request to run a function, which the harness carries out. Also called tool calling. →
Harness
The program around the model, such as a chat app, a coding agent or your own code, that builds each request, runs tools and decides what to keep. →
Hook
Your own code that the harness runs at a fixed point in a session, such as before a tool runs. →
In-context learning
A model picking up a task, format or facts from the text in its window, with no change to its weights. →
KV cache
The model’s stored working for the tokens it has already read; prompt caching reuses it. →
Lethal trifecta
Private data, untrusted content and a way to send data out, together in one agent: the recipe for data theft. →
MCP
The Model Context Protocol: an open standard for connecting AI applications to tool and data servers. →
Plugin
One install that bundles skills, commands, subagents, hooks and MCP settings. →
Pre-training
The large, one-off training run that sets a model’s weights by teaching it to predict the next token. →
Progressive disclosure
Loading only a short description up front and the detail when it is needed. →
Project instruction file
A Markdown file such as AGENTS.md that the harness loads at the start of every session. →
Prompt caching
Reusing the model’s stored working (the KV cache) for an unchanged start of the prompt, which is cheaper and faster. →
Prompt injection
Instructions hidden in text the model reads, such as a web page or tool result, that the model then follows. →
RAG
Retrieval-augmented generation: looking up relevant passages when a question arrives and putting them in the prompt. →
Reasoning model
A model that produces its own hidden or summarised reasoning before answering. Also called a thinking model. →
Sandbox
An isolated place to run code, with limited access to files and the network. →
Skill
A folder of instructions, and optionally scripts and reference files, that loads when a task calls for it. →
Slash command
A saved prompt you trigger by typing / and its name. →
Subagent
A separate agent with its own window, started for a side task, that returns a summary. →
System prompt
The standing instructions the harness sends before the conversation. →
Token
A chunk of text, often part of a word; windows and prices are counted in tokens. →
Tool search
Holding most tool definitions back and letting the model search for the ones it needs. →
Weights
The numbers set during training that hold what a model learned. Also called parameters. →

About this page

A primer on in-context learning and on filling a model’s context well, written for engineers, data scientists and analysts who use language models and coding agents every day.

It is built entirely from public sources: research papers, vendor documentation, open specifications and independent writing, each cited above. Vendor figures are the vendors’ own measurements. Product details, prices and specifications change quickly; they are given as of November 2026.
